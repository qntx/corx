## Native server

```bash
cargo run -p corx-server -- --allowed-origins https://app.example.com
```

or with Docker:

```bash
docker build -t corx .
docker run -e CORX_ALLOWED_ORIGINS='*' -p 8080:8080 corx
```

### Configuration

Every flag maps to a `CORX_*` environment variable.

| Flag / env                                             | Default                                                                 |
| ------------------------------------------------------ | ----------------------------------------------------------------------- |
| `--bind` / `CORX_BIND`                                 | `0.0.0.0:8080`                                                          |
| `--allowed-origins` / `CORX_ALLOWED_ORIGINS`           | required — comma-separated origins, `*`, or empty (native clients only) |
| `--user-agent` / `CORX_USER_AGENT`                     | `corx/<version> (+https://github.com/qntx/corx)`                        |
| `--client-ip-source` / `CORX_CLIENT_IP_SOURCE`         | `ConnectInfo`                                                           |
| `--ip-rate-per-minute` / `CORX_IP_RATE_PER_MINUTE`     | `60`                                                                    |
| `--ip-burst` / `CORX_IP_BURST`                         | `120`                                                                   |
| `--host-rate-per-minute` / `CORX_HOST_RATE_PER_MINUTE` | `120`                                                                   |
| `--max-concurrency` / `CORX_MAX_CONCURRENCY`           | `512`                                                                   |
| `--cache-capacity` / `CORX_CACHE_CAPACITY`             | `100000`                                                                |
| `--metrics-bind` / `CORX_METRICS_BIND`                 | unset — dedicated Prometheus listener address                           |
| `--log-format` / `CORX_LOG_FORMAT`                     | `json` (or `pretty`)                                                    |
| `RUST_LOG`                                             | `info`                                                                  |

Metrics are exported on `--metrics-bind` only, never on the public port:
`corx_requests_total{outcome}` and
`corx_request_duration_seconds{cache="hit"|"miss"|"none"}`.

### Fronting proxy

The binary serves plain HTTP only. Run it behind a TLS-terminating reverse
proxy or CDN — that layer also provides slow-client and header-read timeout
protection, which `axum::serve` does not implement on its own. `/healthz`
is served outside the concurrency limiter so liveness probes still succeed
under saturation.

## Cloudflare Worker

```bash
just worker-dev      # npx wrangler dev with ALLOWED_ORIGINS for localhost:5173
just worker-deploy   # wrangler deploy
```

Configuration lives in `crates/corx-worker/wrangler.jsonc`:

- `compatibility_flags: ["global_fetch_strictly_public"]` — the SSRF control.
- `ratelimits`: `IP_LIMITER` (namespace `1001`) and `HOST_LIMITER`
  (namespace `1002`), each 120 per 60 s.
- `vars.ALLOWED_ORIGINS` — **must be set at deploy time** (empty means no
  browser Origin is allowed: API is then native-client-only);
  optional `USER_AGENT` (for example `--var USER_AGENT:...`) overrides the
  versioned default `corx/<version> (+https://github.com/qntx/corx)`.

```bash
npx wrangler@4.149.0 deploy --var ALLOWED_ORIGINS:https://app.example.com
```

The Cache API works in `wrangler dev` and on custom domains/routes, but it
is a no-op on `*.workers.dev` hostnames — deploy on a route to use it.

Responses are cached in the Cache API under the Worker's own request
origin — `{origin}/v1/preview?url=<encoded target>` — successes for 24 h,
`no_metadata`/`upstream_status` for 1 h, everything else not at all. CORS
is applied after cache reads so stored entries never carry
`Access-Control-Allow-Origin`. Rate-limit denials report
`Retry-After: 60` (the binding period).
